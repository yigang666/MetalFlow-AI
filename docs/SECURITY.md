# RBAC 与安全

来源为 [HTML PRD §03、§05–§09、§12、§15](../MetalFlow_AI_Product_Owner_PRD_v1.html)。授权考虑租户、资源所有者、团队和字段权限。

| 角色 | 业务边界 |
| --- | --- |
| Sales Representative | 负责客户、沟通、自有报价与授权成本，禁止批准自己的超限报价 |
| Sales Manager | 团队客户、供应商报价、利润区间与审批 |
| Finance | 付款节点、到账状态、财务文件 |
| Operations | 订单执行、工厂交付、QC、装运及文件 |
| Tenant Owner / Admin | 用户、角色、集成、业务配置 |
| Platform Admin | 平台运维，默认无租户业务数据权限，必要时走授权和审计的紧急通道 |
| Auditor | 授权范围只读 |

服务端从已验证身份与有效成员资格确定租户。所有查询与写入均执行 tenant scope 和 RBAC。跨团队访问须符合资源授权，客户转移记录审计，成本、毛利、付款信息单独授权。数据库侧隔离与应用侧校验并用。审计覆盖权限变更、归属转移、批准、拒绝和对外发送，记录操作者、时间、行为、目标和结果，排除秘密与无必要的敏感原文。

邮件发送、报价发布、合同签署、银行账户变更、赊销和重大客诉需要人工控制。付款确认依赖可信记录。AI 不得自行承诺价格、库存、交期或账期，不得独自决定重大客诉与信用事项。消息、附件和外部内容是非可信数据。受控工具按发起用户权限重新验证模型建议，外部内容不能改变工具权限。Webhook 验签并防重放，关键动作要求幂等。只有获授权的集成可读取数据或发起外部动作。

## Phase 1 验证计划

- 在 Sandbox 用两个合成租户覆盖 API 与数据库的跨租户读写拒绝、用户和团队作用域及列表过滤。
- 验证未登录拒绝、禁用身份、角色授权变更及拒绝路径的副作用。
- 检查审计可追溯性、维护者访问边界、秘密扫描、依赖风险和日志脱敏。
- 后续业务阶段验证人工审批、防重放、外部内容信任边界及不可变报价版本。

## Phase 1 本地实现边界

- Sandbox 账号由种子创建，统一测试密码由操作者本机生成。密码使用独立盐和 scrypt，会话使用随机令牌，仅保存摘要。
- 登录验证所选租户内的凭据并签发绑定租户的会话。每次受保护请求复核会话、租户状态、账号状态和当前角色。并发刷新仅允许一个请求成功。
- API 显式带租户条件，事务内设置 `metaflow.tenant_id`。RLS 默认拒绝无上下文访问，跨表外键约束租户一致性。运行角色可按请求设置该上下文，因此运行凭据和 API 进程仍在信任边界内。
- 审计表对运行角色只开放读和追加。基础审计记录登录成功、刷新、登出和已认证的权限拒绝，包含操作者、时间、动作与结果。
- 生产身份提供方、限速、会话清理策略、真实数据、生产密钥管理与对外暴露均须在对应批准范围内设计和验收。

## Phase 2 Sandbox CRM

- 每个 CRM 事务从认证身份设置当前操作者及角色，应用与数据库同时验证资源租户与负责人。负责人转移仅允许租户管理角色，并只记录目标与前后负责人 ID。
- XLSX 在内存中解析，限制文件、行、归档展开及逻辑单元格长度。导入拒绝外部关系、宏、有公式的导入单元格和 DTD。工作簿及其链接不触发网络请求。
- 导入预览证明确认由当前会话签名，提交重新计算内容摘要与重复候选。合成账户及固定角色限 Sandbox。生产字段保留、团队作用域和真实样本审批仍待确认。
