## Phase 1 Sandbox

- 以本地合成账户验证认证。密码使用带独立随机盐的 scrypt，随机会话仅以哈希入库，绑定单个租户，30 分钟到期。刷新在同一事务内撤销旧会话并签发新会话。
- 固定基础角色仅覆盖身份读取、用户列表和审计日志。租户邀请、身份供应商和业务授权细则维持待确认。
- 使用迁移/种子管理员和受限 API 数据库账户。API 明确限定租户，每个认证事务设置 PostgreSQL RLS 上下文。
- 当前目录是文档交付包展开目录，没有 Git 历史。本阶段按文件所有权并行工作，检查点写入 harness。

## Phase 2 Sandbox CRM

- 导入采用固定七列表头和预览后提交。以规范化后的公司名、网站域名、联系人邮箱、电话或 LinkedIn 地址精确命中生成建议。候选行由操作者选择跳过或创建独立客户。该规则仅用于 Sandbox 验收，真实业务字段及身份规则待确认。
- CRM 应用查询与 PostgreSQL RLS 同时限制租户和负责人。通过租户级事务锁让导入确认、负责人变更和子记录操作按序完成，避免检查后归属变更。管理角色可见本租户 CRM，Sales 仅可见本人客户。
- 导入回执以租户、工作簿内容和确认行集合幂等。预览证明确认仅带工作簿摘要、重复行索引和会话签名。API 提交时重新核对当前候选。
