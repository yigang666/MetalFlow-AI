# 阶段开发与恢复

1. 读取状态、PRD 和上阶段报告。核验当前阶段已获批准，明确范围、非目标、用户故事与验收条件。
2. 在任务图登记依赖、负责人、互斥路径和验证命令。先评审架构、schema、API 契约和测试设计，再放行实现。迁移由 Database Engineer 统一排序。
3. 调用原生子 Agent 并行处理可独立任务。Team Lead 集成并执行自动测试。发现失败后把命令、退出码、实际和预期结果交给负责人。每个问题最多三轮修复，逐轮记录并用同一验收重测。仍失败标记 BLOCKED，继续未受影响的任务。
4. 请求独立代码和安全审查。修复后重跑受影响检查，最终执行阶段集成及 E2E 验证。维持安全标准和测试断言。
5. 更新文档、状态与证据，交付报告。等待 Product Owner 批准下一阶段。

任务状态为 TODO、IN PROGRESS、DONE 或 BLOCKED。测试结果另外记录 PASS、FAIL、NOT RUN 或 SKIP 及原因。适用质量门包括 lint、类型检查、单元测试、集成测试、E2E、构建、迁移、安全、租户隔离、独立审查。DONE 需要关联证据和已满足的验收。

每次任务移交、冲突或验证结果写入 [状态](../harness/context/STATE.md) 或 [构建日志](../harness/build-log.md)。新会话从最近可核验的 checkpoint 恢复，先检查分支、工作区和关联证据。任何运行应有超时、资源预算、有限重试与隔离输入。报告记录执行摘要、阶段状态、交付内容、Agent 贡献、文件、测试及证据、安全发现、已知问题、决策、阻塞、运行方式和下一步。
